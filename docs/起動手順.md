# ローカル起動手順

## 前提条件

- Docker Desktop（WSL2 インテグレーション有効）
- 以下のリポジトリが同じ親ディレクトリ（メタリポジトリ `character-system/`）に配置されていること

```
character-system/
├── character-db/                      # スキーマ + マイグレーション
├── character-db-infra/                # PostgreSQL + migrate の compose スタック
├── apis/
│   ├── character-api-go/              # Go API 本体
│   └── character-api-go-infra/        # Go API + Redis の compose スタック
└── applications/
    └── character-application-nextjs/  # user-dashboard（このリポジトリ）← ここで作業する
```

ローカルは単一 compose ではなく、**外部ネットワーク `character-db-net` で接続された
3つの compose スタック**で構成される（このネットワークは character-db-infra が作成する）。

## 初回セットアップ（依存順に3スタックを起動）

```bash
# 1. DB スタック（PostgreSQL + Atlas マイグレーション）
cd ../../character-db-infra && docker compose up -d

# 2. API スタック（Go API + Redis）
cd ../apis/character-api-go-infra && docker compose up --build -d

# 3. アプリスタック（このリポジトリ。MySQL + Next.js）
cd ../../applications/character-application-nextjs
cp .env.example .env   # AUTH_GOOGLE_* / INTERNAL_API_KEY 等を編集
docker compose up --build
```

`INTERNAL_API_KEY` は **api-go-infra 側の .env と同じ値**にすること（不一致だと API が 401 を返す）。

## 起動順序（スタック内は自動制御）

```
[character-db-infra]  character-db → character-db-migrate（atlas → views → seeds）
        ↓ character-db-net
[character-api-go-infra]  character-api-redis → character-api
        ↓ character-db-net
[このリポジトリ]  user-db（MySQL）→ user-dashboard（prisma migrate deploy → Next.js）
```

## アクセス先

| サービス                      | URL                   |
| ----------------------------- | --------------------- |
| ユーザーダッシュボード        | http://localhost:3000 |
| キャラクターAPI（デバッグ用） | http://127.0.0.1:8080 |
| キャラクターDB（デバッグ用）  | 127.0.0.1:5432        |
| ユーザーDB（デバッグ用）      | 127.0.0.1:3306        |

## よく使うコマンド

```bash
# このスタックの停止 / 完全リセット（DB ボリューム含む）
docker compose down
docker compose down -v

# ログを見る（各スタックのディレクトリで実行）
docker compose logs -f user-dashboard                                  # ここで
(cd ../../apis/character-api-go-infra && docker compose logs -f character-api)
(cd ../../character-db-infra && docker compose logs -f character-db)

# キャラクター DB マイグレーションの手動再実行（character-db-infra で）
(cd ../../character-db-infra && docker compose run --rm --build character-db-migrate)
```

## ポート公開について

ポート公開は環境別の compose ファイルで管理する:

- `docker-compose.yml`（base）— 公開なし
- `docker-compose.override.yml` — ローカル開発用（自動ロード）。3000 と、デバッグ用の
  3306（ループバック限定）
- `docker-compose.stg.yml` — STG（自宅サーバー）用。3000 のみ公開し、MySQL は公開しない。
  deploy-stg.yml が `-f docker-compose.yml -f docker-compose.stg.yml` で使用する
