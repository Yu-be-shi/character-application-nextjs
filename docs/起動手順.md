# ローカル起動手順

## 前提条件

- Docker Desktop（WSL2 インテグレーション有効）
- 以下のリポジトリが同じ親ディレクトリに配置されていること

```
character-system/
├── api/          # character-api
├── application/  # user-dashboard（このリポジトリ）← ここで作業する
└── db/           # character-db
```

## 初回セットアップ

```bash
# 1. 環境変数ファイルを準備
cp .env.example .env
# .env を編集して各値を設定する

# 2. 全サービスをビルドして起動
docker compose up --build
```

## 起動順序（自動制御）

```
character-db（起動・ヘルスチェック通過）
    ↓
character-db-migrate（マイグレーション実行・終了）
    ↓
character-api（APIサーバー起動・ヘルスチェック通過）
    ↓
user-db（起動・ヘルスチェック通過）
    ↓
user-dashboard（Prisma migrate deploy → Next.js 起動）
```

## アクセス先

| サービス                      | URL                   |
| ----------------------------- | --------------------- |
| ユーザーダッシュボード        | http://localhost:3000 |
| キャラクターAPI（デバッグ用） | http://localhost:8080 |
| キャラクターDB（デバッグ用）  | localhost:5432        |
| ユーザーDB（デバッグ用）      | localhost:3306        |

## よく使うコマンド

```bash
# 全サービス停止
docker compose down

# DBデータも含めて完全リセット
docker compose down -v

# ログを見る
docker compose logs -f character-api
docker compose logs -f user-dashboard

# マイグレーションを手動で再実行
docker compose run --rm character-db-migrate
```

## ポート公開について

`docker-compose.override.yml` でローカル開発時のポートを公開している。
本番環境では `docker-compose.yml` のみを使用し、ポートは公開しない。
