# ローカル起動手順

## 前提条件

- Docker Desktop（WSL2 インテグレーション有効）
- 以下のリポジトリが同じ親ディレクトリ（メタリポジトリ `character-system/`）に配置されていること

```
character-system/
├── platform-infra/                   # 基盤スタック: PostgreSQL + migrate + Go API（character-db-net を作成）
├── apis/
│   └── character-api-go/              # Go API 本体 + schema/migrations（基盤のビルド元）
└── applications/
    └── character-application-nextjs/  # user-dashboard（このリポジトリ）← ここで作業する
```

ローカルは単一 compose ではなく、**外部ネットワーク `character-db-net` で接続された
2つの compose スタック**（platform-infra の基盤 + このアプリ）で構成される。
`character-db-net` は platform-infra が作成し、このアプリは `external` で参加する。

## 初回セットアップ（基盤 → アプリの順に起動）

```bash
# 1. 基盤スタック（PostgreSQL + migrate(atlas→views→seeds) + Go API）
cd ../../platform-infra && docker compose up -d --build

# 2. アプリスタック（このリポジトリ。MySQL + Next.js）
cd ../applications/character-application-nextjs
cp .env.example .env   # AUTH_GOOGLE_* / INTERNAL_API_KEY 等を編集
docker compose up --build
```

`INTERNAL_API_KEY` は **platform-infra 側の .env と同じ値**にすること（不一致だと API が 401 を返す）。

## 起動順序（スタック内は自動制御）

```
[platform-infra]  character-db → character-db-migrate（atlas → views → seeds）→ character-api-redis → character-api
        ↓ character-db-net
[このリポジトリ]  user-db（MySQL）→ user-dashboard（prisma migrate deploy → Next.js）
```

## アクセス先

| サービス                      | URL                   |
| ----------------------------- | --------------------- |
| ユーザーダッシュボード        | http://localhost:3000 |
| キャラクターAPI（デバッグ用） | http://127.0.0.1:8080 |
| キャラクターDB（デバッグ用）  | 127.0.0.1:5432        |
| ユーザーDB（デバッグ用）      | 127.0.0.1:3306        |

## よく使うコマンド

```bash
# このスタックの停止 / 完全リセット（DB ボリューム含む）
docker compose down
docker compose down -v

# ログを見る
docker compose logs -f user-dashboard                                  # ここで
(cd ../../platform-infra && docker compose logs -f character-api)
(cd ../../platform-infra && docker compose logs -f character-db)

# キャラクター DB マイグレーションの手動再実行（platform-infra で）
(cd ../../platform-infra && docker compose run --rm --build character-db-migrate)
```

## ポート公開について

ポート公開は環境別の compose ファイルで管理する:

- `docker-compose.yml`（base）— 公開なし
- `docker-compose.override.yml` — ローカル開発用（自動ロード）。3000 と、デバッグ用の
  3306（ループバック限定）
- `docker-compose.stg.yml` — STG（自宅サーバー）用。3000 のみ公開し、MySQL は公開しない。
  deploy-stg.yml が `-f docker-compose.yml -f docker-compose.stg.yml` で使用する
